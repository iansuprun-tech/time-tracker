## Что это

Личный трекер дня. План пишется накануне, утром день стартует — и план
замораживается. В течение дня блоки трекаются таймером, вечером день
закрывается с оценкой настроения, а из накопленного собирается сводка
для стендапа.

Друзья видят дни друг друга на чтение и комментируют их.

## Стек

Nuxt 4 (Vue 3 + TypeScript) · Postgres 17 · Drizzle ORM · Tailwind 4
Хостинг Vercel, база Neon, авторизация `nuxt-auth-utils`.

## Запуск у себя

```bash
cp .env.example .env     # строку подключения вписать свою

npm install
npm run db:push          # накатить схему
npm run dev              # http://localhost:3000
```

Команды: `npm run dev` · `build` · `typecheck` · `db:push`

## Как это выглядит

Слева — тёмно-зелёная боковая панель с разделами, справа — карточки на светлом
(или тёмном, по настройке системы) фоне. На узком экране панель ложится полосой
сверху, а имя и «выйти» уезжают в шапку контента.

Повторяющиеся куски оформления собраны в `app/assets/css/main.css`
(`.card`, `.field`, `.btn-primary`, `.btn-soft`, `.btn-quiet`, `.chip`, `.muted`,
`.page`, `.page-title`) — иначе половина страниц тихо расходится с остальными
при первой же правке. Акцент везде один — emerald.

## Календарь недели

Главная страница — неделя по часам: семь колонок, сетка растягивается под то,
что в ней есть (по умолчанию 8–20). Заливка — **факт** из `time_entries`, контур —
**план**. Цвет держится за категорию, а без неё — за название, поэтому один и тот же
блок всю неделю одного цвета.

Интервал, перешедший за полночь, режется по суткам: колонка не умеет быть
длиннее дня. Блоки из плана, по которым не было ни таймера, ни окна, собраны
строкой «без таймера» под сеткой — иначе неделя выглядит пустее, чем была.

Блок в сетке открывается карточкой (`BlockPeek`): название, проект, категория,
место, время, заметки и комментарии — с возможностью ответить, не уходя
на день. Внизу карточки ссылка на сам день.

Кликаются и плановые контуры. Раньше у них стоял `pointer-events-none`, чтобы
не перехватывать клик у залитого факта поверх, — но у задачи, по которой таймер
не тикал, никакого факта нет, и открыть её было нельзя вообще ничем. Теперь
контур — кнопка, а факт лежит выше по `z-index` и перехватывает клик сам,
без запрета на события.

Задачи не сегодняшнего дня приглушены. В сетке колонка сама по себе говорит,
какой это день, но глаз считывает цвет раньше заголовка: без приглушения
завтрашняя ночная задача выглядит как текущая.

Данные для карточки берёт `GET /api/block?id=`. В недельную выдачу их не
кладём: семь дней задач со всеми разговорами приезжали бы в каждый заход
на главную ради одной, которую откроют.

Неделя друга — та же страница: `/?userId=<id>`.

## Онлайн и офлайн задачи

У блока есть плановое окно «с — по» (`planned_start_min`, `planned_end_min` —
минуты от полуночи своего дня, поэтому часовые пояса ни при чём) и тип:

| Тип | Кто считает время | Как выглядит в календаре |
|---|---|---|
| **онлайн** | таймер по ходу дня | окно — пунктирный контур (намерение), факт — заливка поверх |
| **офлайн** | никто, время вписано руками | окно и есть факт: сразу заливка |

Офлайн-задаче окно обязательно — без него от неё ничего не остаётся. Её
`actual_min` равен длине окна, поэтому итоги дня и сводка считаются как раньше,
а кнопки «Старт» у такого блока нет.

## Проекты, места и шаблоны

У блока есть место (`blocks.location`) — свободная строка: «офис», «дома»,
«у клиента». В календаре оно показывается под временем, если блок достаточно
высокий, и всегда — в подсказке при наведении.

Есть и проект (`blocks.project`) — к чему задача относится: «Трекер», «Сайт
клиента», «Быт». Категория отвечает на «какого рода работа», проект — на «ради
чего»: одна и та же «встреча» бывает по разным проектам, и смешивать их в одном
поле значит потерять оба разреза. В списке дня проект стоит перед категорией
и помечен акцентом — по нему глаз собирает задачи в кучки.

Шаблоны категорий, мест и проектов лежат в `presets`
(`kind`: `category` | `place` | `project`), у каждого свои. Список пополняется сам: новое значение, введённое в блоке,
запоминается — иначе справочник приходится вести руками, и им перестают
пользоваться. Править его на «Настройках»: добавить, переименовать, убрать.

Переименование тянет за собой блоки того же пользователя, иначе старое значение
остаётся в истории сиротой. Удаление шаблона блоки не трогает: оно убирает
значение только из подсказок.

## Поле времени

Нативный `input[type=time]` показывает «--:-- --», формат берёт из локали
браузера и просит попасть в крошечные стрелки — выглядит недоделанным.
Вместо него `TimeField`: печатаешь как удобно («1030», «10.30», «9») и получаешь
10:30, а рядом список получасовок, чтобы обычный случай закрывался одним кликом.
У поля «по» в списке сразу видна длительность — «+30м», «1ч».

В форме добавления пары полей нет, пока она не нужна: сначала кнопка
«Указать время», а на «Офлайн» поля раскрываются сами и заполняются.

## Форма создания задачи

Форма живёт в шторке: на странице только кнопка «Добавить задачу», по клику
снизу выезжает `AddBlock`. Вросшая в страницу карточка занимала треть телефона
даже тогда, когда ничего не заводят, и все поля в ней весили одинаково.

Внутри выстроена иерархия: сверху строка «Задача · 16 сентября · в плане»,
под ней имя — крупное и без рамки, ниже ряд атрибутов, внизу отдельная полоса
с «Создать». Незаполненный атрибут — тихий чип с пунктиром («Проект»,
«Категория», «Место», «Длительность», «Время»), заполненный подсвечен акцентом:
видно, что выбор сделан руками, а не достался по умолчанию. Словарь этих
состояний — `.chip-empty`, `.chip-attr`, `.chip-set` в `main.css`.

Всё, что открывается поверх, — модалка: сама шторка, каждый список выбора,
карточка задачи из календаря, правка. Общая оболочка — `ModalSheet`, стопка
и блокировка фона — `useModal`.

Приклеенный к кнопке список не выжил: его приходилось позиционировать руками,
он резался прокруткой шторки (список даты упирался в её нижний край и кончался
на середине недели), дрался за z-index и на телефоне выходил мельче пальца.
Модалка снимает весь этот класс бед разом и ведёт себя одинаково везде.

Модалки вкладываются — список даты открывается поверх шторки создания, —
поэтому фон отпирает только последняя закрывшаяся, а Esc закрывает верхнюю.
Иначе вложенный список, закрывшись, разблокировал бы прокрутку под всё ещё
открытой шторкой.

Проект, категория, место и длительность открываются `PickerField` — списком
заведённых значений со строкой «завести новое» на дне. Нативный `datalist`,
стоявший там сначала, на телефоне подсказок не всплывает: поле выглядит пустой
строкой, по ней не догадаешься, что проекты где-то уже есть, и новый заводится
вслепую — дублируя старый с другой заглавной буквы. Набранное в строке фильтрует
список, так что она же служит поиском. После создания блока шаблоны
перечитываются: иначе только что заведённый проект не появится в списке
до перезагрузки страницы.

Строка статуса честно молчит про чужой день: «в плане» или «вне плана» она
пишет, только когда задача уходит в день открытой страницы, — статуса других
дней фронту отсюда не видно.

Окно открывается клавишей **N** — она же написана на кнопке. Хоткей ловится
по коду клавиши, а не по символу: на русской раскладке та же клавиша даёт «т»,
и сравнение с «n» молча перестало бы работать ровно у того, кто в этой раскладке
и сидит. Не срабатывает в полях ввода и поверх открытой модалки. На телефоне
подсказка «(N)» скрыта — клавиатуры там под рукой нет.

Enter в поле названия создаёт задачу, не отходя к кнопке. В «Описании» Enter
переводит строку — там он нужнее, — а отправляет Cmd/Ctrl+Enter. Кнопка «Создать»
живёт в нижней полосе окна, то есть вне самой формы, поэтому браузер сам ничего
не отправит: обработчики повешены руками. В правке то же самое — Enter сохраняет.

«Описание» уезжает первой заметкой блока: отдельного поля под него в базе нет,
а под маркером заметок оно оказывается ровно там, где его станут искать.

Шторка закрывается после создания: результат надо увидеть в списке, ради этого
всё и затевалось. Категория, место, проект и день переживают закрытие — подряд
обычно заводят задачи одного типа, и переоткрыть шторку дешевле, чем набирать
их заново.

## Правка задачи

Правка живёт отдельным окном (`BlockEdit`), открывается карандашом в строке
блока и кнопкой «Править» в карточке из календаря. Раньше менять можно было
только то, для чего в строке блока нашлось место: статус, окно, факт. Название,
проект, категория и место правились единственным способом — удалить и завести
заново.

Оттуда же задача переносится в другой день. `is_unplanned` при переносе
не трогаем: он помнит, входила ли задача в план, когда её заводили, — переезд
эту историю не переписывает. В новом дне задача встаёт в конец: своего места
в чужом порядке у неё нет.

## Удаление и корзина

Удаление мягкое: строка остаётся, проставляется `blocks.deleted_at`, задача
выпадает из всех списков. Настоящее удаление уносило с собой заметки,
комментарии и тайминги — завести задачу заново несложно, а восстановить
разговор по ней нельзя ничем.

Условие `notDeleted` (`server/utils/day.ts`) одно на весь сервер: забыть его
в одном запросе значит вернуть удалённую задачу обратно на экран. Фильтруют
день, неделя, заметки, забытый таймер, копирование плана и подсказки категорий.

`dropDayIfEmpty` считает удалённые блоки за непустые — и это важно: каскад
по `days.id` унёс бы вместе с пустым днём всё, что лежит в его корзине.

Вернуть можно двумя путями. Сразу после удаления внизу экрана всплывает
«Вернуть» (`UndoDelete` в общем макете, состояние — `useTrash`): подтверждение
ловит промах пальцем, но не ловит «передумал», а понять, что список стал
не такой, можно только после удаления. Позже — «Настройки» → «Корзина», где
у каждой задачи написано, сколько заметок и комментариев уедет вместе с ней.

Корзина держит 30 дней (`server/utils/trash.ts`). Планировщика у нас нет,
поэтому просроченное вычищается по ходу: при удалении и при открытии корзины.
Не открывали корзину и ничего не удаляли — старое полежит дольше, и это
дешевле, чем заводить крон ради одной операции.

Подтверждение спрашивают оба места: и ✕ в черновике плана, и «Удалить задачу»
в правке. ✕ раньше срабатывал сразу — рядом с карандашом это ловушка.

## Поле даты

Задача редко приходит в голову в свой день: «позвонить в четверг» надо класть
в четверг, не уходя со страницы. Поэтому в форме создания рядом с типом
и временем стоит `DateField` — кнопка с человеческой подписью («Сегодня»,
«Завтра», «17 сентября»), список ближайшей недели и нативный календарь на дне
списка, для дат, до которых «завтра» не дотягивается.

По умолчанию — день открытой страницы. Выбранный день залипает: подряд обычно
заводят блоки в один день. Если он не совпадает с открытым, чип подсвечен,
а после сохранения под кнопкой встаёт плашка «„Созвон“ — не в этот день»
с кнопкой «Открыть 17 сентября»: иначе блок выглядит пропавшим, страница-то
осталась прежней.

Плашка именно плашка, а не строчка мелким шрифтом: в момент, когда модалка
закрывается, внимание не под кнопкой, и тихую строку там просто не замечают.
Гаснет она при переходе на другой день — там она уже врёт — и по крестику.

## Фиксированные и плавающие задачи

Задача с окном «с — по» стоит колом: созвон в 17:00 остаётся в 17:00, во сколько
бы ни стартовал день. Задача без окна плавающая: у неё есть только длительность,
и она встаёт подряд от начала дня, обтекая фиксированные. Началось утро на два
часа позже — весь хвост уехал, а созвон остался на месте.

Раскладка считается на лету в `shared/utils/schedule.ts` и нигде не хранится:
иначе расчётное время расходится с настоящим планом при первой же правке.
Начало отсчёта — время старта дня, а пока день не начат — 9:00.

Отработанное (`done`) и отменённое (`dropped`) место в дне не занимает: факт по
нему уже нарисован. Блок без окна и без длительности ставить некуда — такие
собраны строкой «без времени» под сеткой.

В интерфейсе фиксированное время помечено 📌, расчётное — знаком ≈. Снять
фиксацию значит убрать окно: кнопка «убрать» рядом с полями времени.

## Заметки и комментарии под маркером

Заметки по блоку и комментарии друзей висят под одним маркером — значок реплики
со счётчиком в ряду кнопок блока. В списке видно, что по задаче что-то сказано,
а сам текст разворачивается по клику. Развёрнутыми они раздували список, и план
переставал читаться с одного взгляда.

Под маркером и заметки, и комментарии: комментарий друга на своём блоке иначе
не видно вовсе — его показывали только с чужой стороны. Панель после отправки
не закрывается, только что написанное должно остаться на виду.

## Восстановление пароля

«Забыли пароль?» на странице входа → письмо со ссылкой `/reset-<токен>`.
Токен живёт час, работает один раз, и в базе от него лежит только sha256-хеш:
утечка таблицы не должна давать вход. Успешный сброс гасит и остальные ссылки
этого человека, после чего сразу пускает внутрь.

Форма отвечает одинаково на любой адрес — иначе она превращается в проверку,
кто здесь зарегистрирован. Чаще раза в минуту письмо не уходит: чужой ящик
не должен заваливаться с нашей помощью.

Письма шлёт Resend одним HTTP-запросом (`server/utils/mail.ts`), библиотеки в
зависимостях нет. Нужны `RESEND_API_KEY` и `MAIL_FROM`; без них в проде ручка
честно говорит, что почта не настроена, а в разработке письмо печатается
в консоль — иначе сброс нельзя проверить на своей машине.

Кто помнит текущий пароль, меняет его на «Настройках», без почты вообще.

## Звуки таймера

Четыре вехи по активному блоку: старт, круглый час, за N минут до планового
времени, план выбран. Плюс необязательный повтор при переработке.

Звуки синтезируются в `useChimes` — файлов нет, репозиторий публичный.
Настройки лежат в `localStorage` (`tt.sounds.v1`), то есть у каждого устройства
свои: на работе тише, дома громче. Страница — `/settings`.

Фоновая вкладка через пять минут тикает раз в минуту, поэтому вехи не
проверяются по тику, а заранее кладутся в аудиопоток: у него свои часы, их
браузер не душит, и звук приходит секунда в секунду. Окно упреждения — 150
секунд, шире худшего тика.

Сон ноутбука останавливает и аудиочасы, так что запланированное расходится с
настенным временем. Расхождение ловится сравнением часов: просроченное
снимается и звучит сразу. За один тик звучит только старшая веха; вехи,
совпавшие по секунде, схлопываются в одну.

Браузер держит звук закрытым до первого жеста. Открывает его клик «Старт»,
а если таймер шёл ещё до открытия страницы — любой первый клик или клавиша.
Звучит только свой начатый день и только пока вкладка открыта.

## Два правила, которые легко нарушить

**План замораживается.** В момент «Старт дня» план становится снимком.
Всё заведённое после этого помечается `is_unplanned` и показывается отдельно.
Без этого план задним числом подгоняется под факт, и сравнивать становится не с чем.

**Владельца нельзя выводить из интерфейса.** Пишущие ручки принимают id блока
снаружи, поэтому каждая запись обязана звать `assertOwnBlock`, а каждое чтение
чужого дня — `assertCanView` (обе в `server/utils/access.ts`). Скрытых кнопок
недостаточно: без этих проверок чужой день правится запросом в обход интерфейса.

## Как дать доступ коллеге

«Друзья» → «Создать» → ссылка копируется в буфер. Одноразовая, живёт 7 дней.
Коллега открывает её, регистрируется прямо там — и вы сразу друзья.

Он видит дни целиком (блоки, тайминги, заметки, настроение, сводку),
изменить не может ничего, комментирует блоки по отдельности и день целиком.

## Деплой

`git push` в `main` — Vercel собирает и выкатывает сам.
Вручную: `vercel --prod`.

Изменения схемы БД: `npm run db:push` сначала на локальную базу, потом
на прод (подменив `.env` на строку Neon).

## Если что-то сломается

| Что упало | Что делать |
|---|---|
| **Vercel** | Данные целы, они в Neon. Код в GitHub — можно развернуть на любом хостинге, поддерживающем Node |
| **Neon** | Данные недоступны. Восстановление на точку во времени есть в дашборде Neon (Settings → History retention), но глубина на бесплатном тарифе — часы |
| **Забыт пароль** | «Забыли пароль?» на странице входа. Если почта не настроена — хеш меняется прямой записью в таблицу `users` |
| **Аккаунт заблокирован** | Худший случай: нужен собственный бэкап |

**Своих бэкапов сейчас нет.** Снять дамп можно обычным `pg_dump` по строке
подключения к Neon — он это разрешает. Стоит завести регулярный дамп
на свою машину: тогда смерть Neon или блокировка аккаунта перестают быть
потерей данных.
