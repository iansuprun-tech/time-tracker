## Что это

Личный трекер дня. План пишется накануне, утром день стартует — и план
замораживается. В течение дня блоки трекаются таймером, вечером день
закрывается с оценкой настроения, а из накопленного собирается сводка
для стендапа.

Друзья видят дни друг друга на чтение и комментируют их.

## Стек

Nuxt 4 (Vue 3 + TypeScript) · Postgres 17 · Drizzle ORM · Tailwind 4
Хостинг Vercel, база Neon, авторизация `nuxt-auth-utils`.

## Запуск у себя

```bash
cp .env.example .env     # строку подключения вписать свою
docker compose up -d     # локальный Postgres на порту 5433
npm install
npm run db:push          # накатить схему
npm run dev              # http://localhost:3000
```

Команды: `npm run dev` · `build` · `typecheck` · `db:push`

## Два правила, которые легко нарушить

**План замораживается.** В момент «Старт дня» план становится снимком.
Всё заведённое после этого помечается `is_unplanned` и показывается отдельно.
Без этого план задним числом подгоняется под факт, и сравнивать становится не с чем.

**Владельца нельзя выводить из интерфейса.** Пишущие ручки принимают id блока
снаружи, поэтому каждая запись обязана звать `assertOwnBlock`, а каждое чтение
чужого дня — `assertCanView` (обе в `server/utils/access.ts`). Скрытых кнопок
недостаточно: без этих проверок чужой день правится запросом в обход интерфейса.

## Как дать доступ коллеге

«Друзья» → «Создать» → ссылка копируется в буфер. Одноразовая, живёт 7 дней.
Коллега открывает её, регистрируется прямо там — и вы сразу друзья.

Он видит дни целиком (блоки, тайминги, заметки, настроение, сводку),
изменить не может ничего, комментирует блоки по отдельности и день целиком.

## Деплой

`git push` в `main` — Vercel собирает и выкатывает сам.
Вручную: `vercel --prod`.

Изменения схемы БД: `npm run db:push` сначала на локальную базу, потом
на прод (подменив `.env` на строку Neon).

## Если что-то сломается

| Что упало | Что делать |
|---|---|
| **Vercel** | Данные целы, они в Neon. Код в GitHub — можно развернуть на любом хостинге, поддерживающем Node |
| **Neon** | Данные недоступны. Восстановление на точку во времени есть в дашборде Neon (Settings → History retention), но глубина на бесплатном тарифе — часы |
| **Забыт пароль** | Восстановления в приложении нет. Хеш меняется прямой записью в таблицу `users` |
| **Аккаунт заблокирован** | Худший случай: нужен собственный бэкап |

**Своих бэкапов сейчас нет.** Снять дамп можно обычным `pg_dump` по строке
подключения к Neon — он это разрешает. Стоит завести регулярный дамп
на свою машину: тогда смерть Neon или блокировка аккаунта перестают быть
потерей данных.
